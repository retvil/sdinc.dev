# SDINC.dev — восемь уникальных экранов проектов

## Назначение пакета
Реализовать за один рабочий проход восемь разных интерактивных экранов внутри существующего сайта. Это не восемь новых сайтов и не копии одной схемы с заменой подписей.

Пакет задаёт дизайн и поведение презентационных экранов. Он не подтверждает готовность описываемых продуктов и не поручает разрабатывать реальные сервисы видеообработки, RAG или публикации.

## Порядок чтения
1. `00-common-requirements.md` — обязательные ограничения и общая приёмка.
2. `01-video-audio-analytics.md` … `08-video-restoration.md` — отдельные ТЗ.
3. `09-integration-and-acceptance.md` — интеграция и проверка всего набора.
4. `10-agent-message.md` — готовое сообщение агенту для выполнения за один проход.

## Уникальность
| Направление | Центральный элемент | Основное действие |
|---|---|---|
| Видео- и аудиоаналитика | Две связанные временные дорожки | Выбрать событие и сопоставить его с дорожками |
| Игровые проекты | Небольшая тактическая сетка | Пройти локальный демонстрационный маршрут |
| Открытые разработки | Каталог модулей и паспорт репозитория | Выбрать подтверждённую разработку и изучить её |
| RAG-системы | Вопрос, фрагменты источников и ответ | Проследить происхождение ответа |
| Собственный чат-бот | Ветвящийся диалог | Пройти локальный сценарий общения |
| Аналитика звонков | Дорожки участников и стенограмма | Перейти к реплике и её контексту |
| Автоматизация коротких видео | Конвейер из шести стадий | Исследовать вход и результат каждого этапа |
| Реставрация видео | Синхронное сравнение до/после | Сдвинуть разделитель и рассмотреть участок |

## Исходная база
По отчётам владельца: локальный коммит `7b8fab1` содержит принятый этап «Связь». После него менялись `src/data/projects.ts`, `src/scene/renderer.ts`, `src/scene/state.ts`, `src/styles/global.css` для восьми направлений. Фактическое рабочее дерево нужно проверить перед началом: пакет не является снимком репозитория.

Визуальное согласование списка 40/60 и уплотнённых отступов не было завершено. Эти значения не объявлять окончательным эталоном. Остальная принятая оболочка сохраняется.

## Что считать одним проходом
Изучение → реализация всех восьми экранов → интеграция → ограниченная проверка → исправление найденных регрессий → итоговый отчёт. Не останавливаться после плана или первого экрана и не запрашивать согласование каждого шага. Остановка допустима при конфликте с чужими изменениями, риске потери данных или необходимости изменения вне разрешённой области.

## Что не разрешено
Commit, push, deploy, реальные публикации, отправка сообщений, загрузка пользовательских файлов во внешние сервисы, подключение платных API, сбор персональных данных. Никаких секретов в клиентском коде.
