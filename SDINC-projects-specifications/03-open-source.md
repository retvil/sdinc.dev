# 03. Открытые разработки

## Задача
Сделать каталог реальных программных модулей с паспортом выбранной разработки. Не превращать экран в список придуманных репозиториев.

## Подтверждённая информация
Из контекста известен репозиторий `retvil/sdinc.dev` — текущий сайт-портфолио. GitHub владельца — `retvil`. Это не разрешение автоматически включать все репозитории аккаунта и приписывать их содержимое.

Используй существующие подтверждённые данные проекта и локальные сведения текущего репозитория. Если других подтверждённых разработок нет, одного реального элемента достаточно: сделать содержательную презентацию портфолио, а не заполнять каталог фиктивными карточками. Не выполнять массовое внешнее исследование в рамках этого прохода.

## Композиция
- Каталог реальных разработок или модулей слева/сверху.
- Паспорт выбранного элемента: назначение, источник, подтверждённые свойства.
- Для текущего портфолио можно показать выбираемые области «Интерфейс», «Навигация», «Данные», если их наличие подтверждено кодом. Это модули одного проекта, не отдельные репозитории.
- Короткие текстовые пояснения без вывода исходного кода целыми файлами.
- Кнопка/ссылка «Исходный код» только для подтверждённого адреса.

## Взаимодействие
Выбор разработки или модуля обновляет паспорт. Переход на GitHub выполняется только отдельной нативной ссылкой, не выбором карточки. Для внешней HTTPS-ссылки сохранять принятую политику target/rel. Никаких API-ключей, запросов GitHub при загрузке, счётчиков звёзд, фиктивных языковых процентов или статусов CI.

Если доступен только один репозиторий, основной интерактивный набор — его реальные внутренние модули. Шаг ротора циклически выбирает эти модули, confirm раскрывает пояснение. Confirm не должен случайно открывать внешний сайт вместо исследования экрана.

## Локальное состояние
Выбранная разработка и её выбранный модуль; идентификаторы не зависят от позиции в общем массиве проектов.

## Критерии приёмки
На экране нет выдуманных продуктов и технологий. Текст выводится из проверенных сведений, а не предположений по названию репозитория. Экран остаётся законченным даже с одной разработкой. В итоговом отчёте перечислить реально использованные источники сведений и какие репозитории добавлены.
