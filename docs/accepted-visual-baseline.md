# SDINC — принятая визуальная база (единая поверхность дисплея)

Статус: **принято пользователем** (визуальная приёмка текущего просмотра,
явных графических дефектов нет). Базовый коммит: `97a160e`
`feat(display): shared clean screen surface for projects and project modes`.
Ветка `main`, git локальный, публикация не настроена.

## Принятая архитектура отображения

- Один физический дисплей, одна поверхность, одно стекло. При смене раздела
  меняется информация, а не материал экрана.
- Слои рендера:
  1. `master` — утверждённый 4K-референс целиком (корпус + стартовый экран).
     Профиль использует его напрямую, без изменений.
  2. `screen-surface.png` (2088×1354, вырезка `[1250,588]–[3338,1942]`) —
     чистая внутренняя поверхность дисплея, восстановленная из референса:
     сменяемый стартовый контент (двойник, кольца, узлы, подписи, соединения,
     карточка) удалён масочной реконструкцией; запечёнными оставлены заголовок
     «SDINC / PERSONAL SYSTEM» с боковыми линиями, нижняя навигация,
     разделитель, блик, виньетка, кромка.
  3. Прозрачный HTML-контент текущего режима (projects / project) поверх
     листа; его область — между общим заголовком и общей нижней навигацией.
- Генератор: `scripts/make-screen-surface.py` (PIL+numpy, воспроизводимо);
  артефакты: `docs/screen-surface/screen-surface-mask.png`,
  `screen-surface-compare.png`.
- Логика режимов — машина состояний `profile/projects/project/contact` в
  `src/scene/state.ts`; данные — `src/data/demo.ts`, `src/data/projects.ts`.
- Видимость карточки направления — единое правило `syncLiveCard()`:
  `hidden = !(режим profile И активный узел ≠ LLM)`; это единственное место
  кода, которое показывает/скрывает live-card. Для LLM карточка растровая,
  запечённая в master, HTML-дубль не создаётся.
- Выбор направления: `selectNode(key, mark)` — `mark=true` только для явных
  пользовательских действий (клик по узлу, шаг/подтверждение ротора) и ставит
  флаг `userSelected`; программные вызовы (`init`, `resetView`, синхронный
  возврат) идут с `mark=false` и флаг не трогают.
- Фокус при смене режима — `refocusAfterModeChange()`: если триггер —
  постоянный контроль (запечённый ряд вкладок, кнопки корпуса; видимы во всех
  режимах), фокус остаётся на нём; если триггер скрылся вместе с экраном —
  фокус переносится на подходящий элемент нового экрана (пункт списка /
  заголовок проекта / заголовок «Связь» / выбранный узел в профиле). Фокус
  не оставляется на body; скрытая карточка и неактивные экраны не фокусируются.
- Экран «Связь» — принятая реализация: три реальных контакта (Email →
  Telegram → GitHub, данные подтверждены пользователем) на общей поверхности
  без новых панелей/стекла. Обычный ul/li (без listbox-ролей над смешанным
  содержимым): нативная кнопка выбора (`aria-pressed`, ровно один выбран,
  старт Email), отдельная нативная ссылка основного действия, отдельная
  кнопка копирования (`navigator.clipboard.writeText` без legacy-fallback;
  результат в строке `role="status"`/`aria-live="polite"`). Выбор сам по себе
  не открывает ссылки; ротор — циклический выбор, подтверждение — основное
  действие выбранного. Контакты, их графику и управление не перерабатывать.
- Раздел «Проекты» — принятая реализация: восемь направлений работ в
  подтверждённом порядке (видео- и аудиоаналитика → игровые проекты →
  открытые разработки → RAG-системы → собственный чат-бот → аналитика
  звонков → автоматизация коротких видео → реставрация видео). Все пункты —
  `kind: 'direction'` (направление работ: описание без продуктовых
  заявлений, пометка «НАПРАВЛЕНИЕ РАБОТ»). Демонстрационный образец
  структуры удалён по требованию владельца: раздел содержит только восемь
  направлений. Список: ширина 40%, сжатые вертикальные отступы и
  промежутки (шрифты не менялись).
  СТАТУС: функционально принято; визуальная приёмка компоновки списка
  (ширина/отступы/баланс с превью) — открыта.
- Экраны направлений — реализованы по пакету ТЗ
  (папка `SDINC-projects-specifications/` удалена из репозитория): диспетчер
  `src/projects/` (registry + отдельный модуль на направление), ленивый маунт
  в общий хост проектного экрана, ротор делегируется активному экрану.
  Направления — направления работ, не продукты; синтетические материалы
  помечены на самих экранах. Реализация НЕ проходила визуальную приёмку
  владельца.

## Зафиксированные ограничения принятой версии

1. **Восстановленный фон.** Области под удалённым контентом — реконструкция
   интерполяцией окружающих пикселей (исходной скрытой поверхности в плоском
   растре никогда не существовало). Это не извлечённый оригинальный слой.
   Автоматический ghost-чек на момент приёмки: residual mean 0.115 / p99 3 /
   max 15 (высокочастотная остаточная структура внутри маски).
2. **Демонстрационное содержимое.** Раздел проектов содержит только восемь
   направлений работ; демонстрационный образец структуры удалён по требованию
   владельца. Никаких выдуманных достижений, клиентов, цифр и технологий.
3. **Мобильная версия отложена.** Компоновка десктопная (базовый канвас
   1536, прибор 960–1536 px); на узких экранах — горизонтальная прокрутка
   внутри контейнера. Мобильная адаптация — отдельная будущая задача.
4. **Диагностический статус метрик.** MAE нейтрального профиля 1.209
   (MOD-зона 2.141) — диагностическая справка по методике B (скриншот
   1536×1024 vs референс Lanczos), не «процент сходства». Нулевой дифф вне
   панели и низкий MAE не доказывают отсутствие локальных дефектов —
   граница и переходы проверяются визуально.
5. Растровые надписи в проектных экранах отсутствуют (весь текст — HTML),
   но надписи корпуса и профиля остаются запечёнными (принято).

## Регрессионные сценарии поведения (C/D) — обязательны при любых правках

Состояния и переходы, которые не должны ухудшаться:

1. **Подсветки узлов:** hover — мягкое кольцо по кругу узла; уход указателя —
   кольцо исчезает полностью; active — яркое кольцо при удержании;
   selected — постоянное кольцо + свечение, `aria-pressed` синхронно.
2. **Совместность:** selected на одном узле + hover на другом — различаются,
   не конфликтуют; hover не меняет выбор.
3. **Focus-visible:** Tab/Shift+Tab — контурное кольцо по форме узла, без
   прямоугольной рамки; фокус заметен и не зависит от мыши.
4. **Кнопки корпуса:** masked-лицо появляется только при нажатии; пластина
   и подписи не сдвигаются.
5. **Регулятор:** клик/стрелки/колесо/Enter/Space; в profile — направления,
   в projects — пункты списка, в project — компоненты; контекстное
   подтверждение; с одним проектом прокрутка без ошибок и пустого выбора.
6. **Путь данных:** профиль → список (фокус на выбранном пункте) → выбор
   обновляет превью → «Открыть» → экран проекта → «← К списку» (выбор и
   фокус сохранены) → профиль (стартовый экран восстановлен полностью).
7. **Изоляция экранов:** скрытые элементы исключены из Tab-порядка и кликов
   (`hidden` + `pointer-events`); общие заголовок и вкладки целы во всех
   режимах, контент их не перекрывает.
8. **Корпус:** цельный, MOD 1.0 и маркировки без швов; при переключении
   режимов корпус и стекло не меняются.
9. **Сборка:** `npm run build` exit 0, `tsc --noEmit` exit 0, консоль браузера
   без ошибок.
10. **Карточка направления:** принадлежит только режиму profile; единое
    правило `syncLiveCard()`: видимость = (режим profile) И (активный узел ≠
    LLM). Вне profile скрыта и недоступна для фокуса/кликов; в profile
    восстановлена без дублирования с растровой карточкой LLM. «Связь» —
    отдельное состояние на общей поверхности с честной пометкой «Контакты ещё
    не добавлены» (запечённый заголовок и вкладки целы).
11. **Нейтральное первое открытие:** при старте и после `resetView` ни один
    узел не имеет selected-кольца, live-card скрыта (активен LLM — растровая
    карточка), графика соответствует принятой нейтральной базе; `aria-pressed`
    следует активному направлению.
12. **Явный выбор и возврат:** выбранный пользователем узел (мышь или
    регулятор) сохраняется; после возврата в профиль из любого раздела
    восстанавливаются выбранный узел, его карточка (по правилу live-card),
    постоянное selected-кольцо и `aria-pressed`. Возврат без явного выбора
    остаётся нейтральным. Hover не восстанавливается и не смешивается с
    selected; для LLM HTML-карточка не показывается поверх растровой.
13. **Фокус при смене режима:** триггер-вкладка или кнопка корпуса, оставаясь
    видимой, удерживает фокус; скрытый триггер передаёт фокус подходящему
    элементу нового экрана. `activeElement === body` не считается корректным
    результатом смены режима.
14. **Маршруты (мышь и клавиатура):** проверено для всех четырёх узлов:
    выбор → проекты → проект → связь → профиль; Tab/Shift+Tab продолжаются
    после возврата без прыжка к началу страницы. Tab-порядок: узлы и вкладки
    профиля → содержимое экрана → кнопки корпуса → ротор (последний;
    Tab с него уходит в браузерный UI — стандартный wrap, не потеря внутри
    устройства).
15. **Связь:** отображения и ссылки соответствуют подтверждённым данным
    (Email `Hello@sdinc.dev` / `mailto:Hello@sdinc.dev`; Telegram
    `@Nod33Eset` / `https://t.me/Nod33Eset`; GitHub `retvil` /
    `https://github.com/retvil`), порядок Email → Telegram → GitHub; ровно
    один выбранный контакт, выбор переживает разделы; выбор не открывает
    ссылки; копирование доступно с клавиатуры, неудача показывает точное
    значение и просьбу скопировать вручную — никогда «Скопировано»; без
    demo-пометок и неподтверждённых обещаний.
16. **Проекты:** восемь направлений в одном столбце, без переносов названий,
    обрезки и наложений на запечённые вкладки; выбор синхронизирует превью и
    пометку «НАПРАВЛЕНИЕ РАБОТ»; ротор циклит все пункты; экран направления
    показывает описание и пометку «НАПРАВЛЕНИЕ РАБОТ» (без схемы/компонентов/табов —
    они вне Tab-порядка); ротор и подтверждение на экране направления не падают
    и не меняют режим; возврат сохраняет выбор и фокус; другие разделы не
    затронуты.

Каждое из них — в статусе «Наблюдалось однократно в dev, повторно не
воспроизведено, причина не установлена». Не считать их исправленными или
артефактами тестирования. Протокол при повторении любого из них: остановить
прогон; сохранить последовательность действий, активный режим, выбранный
узел и контакт, activeElement, событие, после которого изменилось состояние,
консоль и доступный trace/скриншот. Не вносить предположительный фикс без
установленной причины.

## Правила дальнейших изменений

- Не менять фон, виньетку, блики, координаты дисплея
  (`SCREEN_SURFACE_BOUNDS`/`SCREEN_CONTENT_BOUNDS`) и геометрию корпуса ради
  снижения MAE или иных технических метрик.
- Текущая реализация машины состояний (`state.ts`: режимы, `userSelected`,
  `syncLiveCard`, `refocusAfterModeChange`), фокуса и порядка Tab — рабочая
  база следующего этапа. Самостоятельно (без явного указания пользователя)
  графику, машину состояний, фокус и Tab-порядок не менять.
- Новые commit/push/deploy — только после отдельного разрешения пользователя.
  Существующие локальные коммиты не откатывать.
- Любое изменение внешности/управления сверять с регрессионными сценариями
  выше и проходить визуальную приёмку.
- См. также `docs/stage-c-interactive-states.md` (подсветки и их фиксация).
