# AGENTS.md — SDINC (sdinc.dev)

Краткое руководство для AI-агентов, работающих в этом репозитории.
Человеческие спецификации — в `SDINC_design_brief_v2.md` и `SDINC-projects-specifications/`;
это только «как устроен код и что нельзя ломать».

## Что это

Личный сайт-прибор в стиле Fallout Pip-Boy: ретрофутуристический «утопленный
дисплей» внутри оливково-серого корпуса. Статичный сайт (Astro, без фреймворка),
публикуется на GitHub Pages (домен `sdinc.dev`, см. `astro.config.mjs`).

## Стек

- **Astro 5** (`src/pages/`) + чистый TypeScript. Никаких React/Vue.
- Один `index.astro` рендерит устройство через `src/scene/renderer.ts`.
- Состояние — `src/scene/state.ts` (единый `device`-экземпляр).
- Данные — `src/data/` (проекты, контакты, направления).
- Стили — `src/styles/global.css` (+ `projects.css`, `effects.css`, `editor.css`),
  все размеры — в `cqw` (container-query units от `.device`).

## Визуальная база — ключевое правило

Корпус и стартовый экран — это **одина утверждённая 4K-растра**
(`public/assets/device/SDINC_reference_4K_conservative.png`), на которую накладывается
прозрачный интерактивный слой (вкладки, узлы, портрет, регулятор).

- **Не «чинить» и не перепаинтовать растровый корпус** без явного согласования с владельцем —
  база визуально принята (`docs/accepted-visual-baseline.md`).
- Меняя что-то в дисплее, не двигайте корпус. HTML-панели не должны
  перекрывать физические вкладки (нижний ряд PROFILE/PROJECTS/CONTACT) или
  «затекают» за правую кромку зелёного стекла.
- Координаты дисплея зафиксированы в `renderer.ts` (`SCREEN_SURFACE_BOUNDS`,
  `SCREEN_CONTENT_BOUNDS`). Не меняйте их «по метрикам» — только при явном разрешении.

## Что реализовано (рабочее, не трогайте без причины)

- **8 направлений работ** (`src/projects/screens/*.ts`): media-analytics, game,
  open-source, rag, chatbot, call-analytics, short-video, restoration.
  Все полные, с `enter/leave/step/confirm` (поворот регулятора).
- **Экраны уровней**: список проектов (превью) → detail (описание) → demo (интерактив).
- **Данные — демонстрационные.** В `src/data/projects.ts` честно помечено, что
  направления не являются завершёнными проектами. Не выдумывайте факты о владельце.
- Тесты: `npx vitest run` (юнит) + `npx playwright test` (визуальные, 17 сцен).

## Демо-данные — правило честности

Контент (тексты проектов, результаты, RAG-ответы) **демонстрационный**.
Не наполняйте его выдуманными достижениями, цифрами или «доказательствами».
Если владелец даст реальные данные — замена только его текстами, без «улучшений».

## Как проверять

```
npx astro check          # типизация (0 ошибок)
npm run build            # сборка dist/
npx vitest run          # юнит-тесты
npx playwright test     # визуальная регрессия (нужен preview-сервер на 4322)
```

Для `playwright`: `npm run preview` (порт 4322) + `npx playwright test`.
Базовые снимки в `e2e/visual.spec.ts-snapshots/`.

## Коммиты / push / деплой

- **Локальные коммиты** — по явном запросе.
- **`git push`** и **деплой (GitHub Pages)** — только после отдельного явного
  разрешения владельца. Не публикуйте без спроса.

## Не трогайте

- Растровую базу корпуса/дисплея (см. выше).
- Координаты `SCREEN_*_BOUNDS`.
- Машина состояний и порядок Tab (без необходимости).
- Не добавляйте фреймворк или крупные библиотеки.
