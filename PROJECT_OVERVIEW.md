# SDINC.dev — Суть проекта

> Подготовительная фиксация сути (этап 1 перед исследованием и аудитом).
> Основано на фактическом коде, а не на названиях. Обновлено 2026-11-18.

## Что это
Личный сайт-портфолио владельца (retvil / SDINC), оформленный как **Pip-Boy-прибор**:
ретрофутуристический «дисплей в стекле» с физическим ротором. Не обычный веб-сайт —
это **интерактивный прибор**, который нужно крутить/нажимать/фокусировать.

Ключевой дизайнерский принцип (решение, из которого растёт весь код):
весь корпус устройства — **один цельный 4K-мастер-растр**
(`public/assets/device/SDINC_reference_4K_conservative.png`, 3840×2560).
Поверх него накладываются тонкие **HTML/CSS-слои** (вкладки Профиль/Проекты/Связь,
ротор, кнопки секций, LLM-карточка). Интерактив — **vanilla TypeScript**
(без React/Vue), звук — WebAudio, статика — Astro.

## Какую задачу решает
Показать направления работы владельца (видео/аудио-аналитика, игры, RAG, чат-боты,
колл-аналитика, короткие видео, реставрация, open-source) так, чтобы
1. **понимание шло от общего к частному** (level-2 описание → level-3 работающая демо),
2. **ничего не было выдумано**: демо используют явное «демонстрационные данные»,
   контакты — только подтверждённые каналы (Email/Telegram/GitHub),
3. прибор **работал как прибор**: физический ротор + экранное управление, честный
   фокус, доступность (aria-live, focus-инварианты).

## Целевой пользователь
- Посетитель портфолио: хочет за 20 сек понять, чем занимается владелец, и
  пощекотать «прибор» (ротор, вкладки).
- Кандидат на позицию / заказчик: хочет увидеть конкретные, проверяемые работы
  (8 направлений, каждое с описанием и работающей демонстрацией).
- Владелец (разработчик): хочет, чтобы контент редактировался без перекомпиляции
  графических слоёв — данные в `src/data/*.json`, графики — один мастер-растр.

## Ключевые сценарии (заложены в коде)
1. **Профиль** — выбор из 4 направлений-«узлов» (Vision/LLM/Auto/System),
   живой LLM-карточки. Ротор крутит узлы; Enter — подтвердить.
2. **Проекты** (level-1) — список из 8 направлений; ротор листает, Enter — открыть.
3. **Открытый проект** (level-2) — страница «понять» (essence/problem/approach/
   capabilities/outcome, 4 макета: compare/thesis/flow/split).
4. **Демо** (level-3) — по запросу «Демонстрация» — одна из 8 самодостаточных
   экранов-прототипов (например `game.ts`: тактическое поле 5×5 на SVG, ходы
   стрелками/ротором). Состояние экрана хранится в локальном замыкании — при
   повторном открытии сессии оно сохраняется.
5. **Связь** — 3 канала (Email/Telegram/GitHub); ротор выбирает, Enter — открыть
   ссылку / скопировать адрес (честный результат, без фейкового «скопировано»).
6. **Ротор** — единый физический детент: кликает всегда, логика зависит от режима
   (листает узлы / проекты / контакты; в демо — передаёт шаг активной экрану).

## Архитектурный каркас (что уже есть)
- `src/scene/` — `DeviceState` (машина режимов + ротор + делегирование),
  `renderer.ts` (сборка HTML-слоёв поверх мастера), `sound.ts` (WebAudio),
  `assets.ts` (карта asset-путь → `/assets/device/…`), `source-lib.ts` (dev-only).
- `src/projects/` — `registry.ts` (одна ленивая инстанция на экран, общий host,
  делегирование ротора) + 8 модулей-экранов + `previews/`.
- `src/data/` — `projects.json`, `contacts.ts`, `demo.ts` (4 узла-направления).
- `src/components/LayerEditor.astro` — DEV-only редактор слоёв (вырезан из dist).
- Тесты: vitest (50 unit) + Playwright visual (16, 4K). CI: GitHub Actions → Pages.

## Что за этим стоит (владение / вехи)
Степень D (текущая): прибор с 8 направлениями + 8 работающими демо + честная связь.
Владелец-документация фиксирует вехи (A0–A5, B0–B1, C0–C1, D0–D2) — от первого
растра до текущего состояния. Реестр графических артефактов и CI-инварианты —
в `docs/`.
